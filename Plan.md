# Tijori — Build Plan

> **Tijori** (Hindi for "strongbox") turns any USB pen drive into a strongly encrypted vault that opens on macOS, Linux and Android. Install the app, plug in the drive, enter the password, and the files are there.
>
> This file is the single source of truth for building Tijori with Claude Code. It contains the decisions, the architecture, the milestones with acceptance criteria, and (in Appendix A) the complete on-disk format specification.

**Scope of this version**

| Platform | Status | Technology |
|---|---|---|
| macOS | v1 | Tauri 2 desktop app + `tijori` CLI |
| Linux | v1 | Tauri 2 desktop app + `tijori` CLI |
| Android | v1 | Native Kotlin + Jetpack Compose, Rust core via UniFFI |
| Windows | Later | Not in this plan (the core must stay portable so it can be added) |
| iOS | Future version | Not in this plan |

## 0. Rules for Claude Code (read first)

1. **Read this whole file before writing code.** Then work milestone by milestone, in order. Do not start a milestone until the previous one meets its acceptance criteria.
2. **Never invent cryptography.** Use only the primitives and constructions in Appendix A. If something seems to need a new construction, stop and ask.
3. **The spec wins.** Copy Appendix A into `spec/SPEC.md` in Milestone 0. If code and spec disagree, the code is wrong. Any spec change must be proposed to the user first, then made in `spec/SPEC.md` and the test vectors in the same commit.
4. **Tests first for `core/`.** Every format and crypto function gets unit tests, property tests (`proptest`) and test-vector tests before it is used elsewhere.
5. **No `unsafe` in `core/`.** Put `#![forbid(unsafe_code)]` at the top of `core/src/lib.rs`. Other crates may use `unsafe` only where a dependency requires it, with a `// SAFETY:` comment.
6. **Secrets hygiene.** All keys, passwords, keyfile bytes and plaintext buffers holding keys use `zeroize` / `secrecy` types. Never log, print, `Debug`-format or serialize a secret. Never send a key to the Tauri frontend or to Kotlin.
7. **No network access.** No crate, app or script may contact the network at runtime. No telemetry, no update checks in v1.
8. **Small, reviewable commits.** One logical change per commit, with Conventional Commit messages (`feat(core): …`, `test(core): …`, `fix(cli): …`).
9. **Ask before destructive or irreversible actions**, such as formatting a drive, deleting user data or changing the format version.
10. **When unsure, ask.** Prefer a short question over a guess for anything touching security or the on-disk format.

## 1. Decisions already made

| Topic | Decision |
|---|---|
| Name | Tijori |
| Drive file system | exFAT (readable on every target OS); Tijori stores an encrypted vault folder on it |
| Core language | Rust, one shared core for every platform |
| Desktop app (macOS, Linux) | **Tauri 2** with a React + TypeScript + Vite frontend |
| CLI | Rust, `clap` |
| Android | Kotlin + Jetpack Compose; Rust core through **UniFFI** |
| iOS, Windows | Deferred; keep `core/` free of platform-specific code |
| Crypto library | **`dryoc`** (pure Rust, libsodium-compatible) — checked against vectors generated by real libsodium (PyNaCl) |
| Password hashing | Argon2id v1.3, lanes = 1; desktop default 256 MiB, Android default 128 MiB, tuned to about 1 s |
| Encryption | XChaCha20-Poly1305 (keys, root pointers) and secretstream XChaCha20-Poly1305 in 64 KiB chunks (files, folders) |
| File names and folders | Encrypted; tree of directory objects, hash-linked |
| Size hiding | Padmé padding, **on by default**, can be switched off per vault |
| Crash safety | Copy-on-write commits with two alternating root pointers (A/B); no journal |
| Unlock methods | Password; password + keyfile; 24-word recovery phrase (always generated, shown once with a warning, saving it is optional) |
| Access modes | **Mount** (vault appears as a folder in Finder / file manager, hardened) is the default; **Private mode** keeps everything inside the app. A vault setting can force Private mode only |
| In-app editing | Full file management (add, delete, rename, folders); built-in viewers for images and PDF; small built-in plain-text editor; other files open in their usual app from a RAM disk, re-encrypted on save, wiped on close |
| Licence | Fully free and open source. **Apache-2.0** for `spec/`, `core/`, `ffi/`; **GPL-3.0-or-later** for `cli/`, `mount/`, `desktop/`, `android/` |
| Monetisation | None |

### Defaults for the spec's open questions (change only if the user says so)

| Open question | Default for v1 |
|---|---|
| Very large folders | One object per directory; limit 200,000 entries. B-tree split is a v1.1 idea |
| Hardware security keys | Not in v1; `slot_type` 4 reserved for FIDO2 later |
| Hiding keyslot types | Not hidden in v1 (documented leak) |
| exFAT timestamps | Best effort: set modified/accessed time to 2000-01-01 on every vault file; document what still leaks per OS |
| Recovery phrase language | English BIP-39 word list only |

## 2. Architecture

```
                ┌──────────────────────── exFAT pen drive ────────────────────────┐
                │  README-TIJORI.txt   TIJORI/ vault.header(.bak) vault.root.a/b   │
                │                              objects/xx/<id>.tjo                 │
                └───────────────────────────────▲──────────────────────────────────┘
                                                │  Storage trait (read / write_atomic / list / remove …)
                     ┌──────────────────────────┴──────────────────────────┐
                     │                 tijori-core (Rust)                  │
                     │  crypto · format · vault engine · padding · names   │
                     │  password strength · recovery phrase · rollback    │
                     └───────┬───────────────┬───────────────┬─────────────┘
                             │               │               │
                    tijori-cli (Rust)  tijori-mount (FUSE)  tijori-ffi (UniFFI)
                             │               │               │
                     tijori-desktop (Tauri 2)│        android/ (Kotlin)
                     Rust commands ⇄ React UI│        Compose UI, SAF storage,
                     uses core + mount ──────┘        DocumentsProvider
```

Key principles:

- **`core/` knows nothing about the OS.** It talks to the drive only through a `Storage` trait. Desktop uses a `std::fs` implementation; Android implements the trait in Kotlin on top of the Storage Access Framework via a UniFFI callback interface.
- **Frontends never touch crypto.** CLI, desktop and Android call the `Vault` API only.
- **Keys stay in Rust.** The Tauri frontend and Kotlin code receive file lists, file contents and status — never keys.

## 4. Tech stack

| Need | Crate | Notes |

| CLI | `clap` (derive), `indicatif`, `rpassword` | Never echo passwords |

| App data dirs | `directories` | |

| Android bindings | `uniffi` | Kotlin bindings, callback interface for storage |

| Security tooling | `cargo-deny`, `cargo-audit`, `cargo-fuzz`, `clippy -D warnings` | |

### Desktop frontend

React 18+, TypeScript (strict), Vite, a small component library or plain CSS (keep the bundle small), `@tauri-apps/api` v2. No remote fonts, scripts or images. Strict Content Security Policy.

### Android

Kotlin, Jetpack Compose, Material 3, minSdk 26, targetSdk latest stable. Rust built with `cargo-ndk` for `arm64-v8a`, `armeabi-v7a`, `x86_64`. Kotlin bindings generated by UniFFI. Coroutines for all vault calls (never on the main thread).

### Test-vector generator

Python 3.12 + PyNaCl (real libsodium) + `hashlib` (BLAKE2b with salt/person for `crypto_kdf`) + `cbor2` + `mnemonic`. Lives in `spec/generator/`; output committed to `spec/vectors/`.

## 5. Core library design

### 5.1 Storage trait (sketch — refine in Milestone 2)

```rust
/// Paths are relative to the vault folder `TIJORI/`, '/'-separated, ASCII only.
pub trait Storage: Send + Sync {
    fn read(&self, path: &str) -> Result<Vec<u8>, StorageError>;
    fn open_read(&self, path: &str) -> Result<Box<dyn Read + Send>, StorageError>;
    /// Write to `<path>.tmp`, flush + fsync, rename to `path`, fsync the parent folder.
    /// If the platform cannot rename over an existing file, delete then rename
    /// (the A/B root scheme tolerates this).
    fn write_atomic(&self, path: &str, data: &[u8]) -> Result<(), StorageError>;
    /// Streaming variant for large objects; `commit()` performs the same tmp→rename dance.
    fn create_writer(&self, path: &str) -> Result<Box<dyn AtomicWriter>, StorageError>;
    fn create_exclusive(&self, path: &str, data: &[u8]) -> Result<(), StorageError>; // lock file
    fn list(&self, dir: &str) -> Result<Vec<String>, StorageError>;
    fn exists(&self, path: &str) -> Result<bool, StorageError>;
    fn remove(&self, path: &str) -> Result<(), StorageError>;
    fn mkdir_all(&self, dir: &str) -> Result<(), StorageError>;
    /// Best effort: set modified/accessed time to 2000-01-01T00:00:00Z.
    fn neutralize_times(&self, path: &str) -> Result<(), StorageError>;
}
```

Implementations: `StdFsStorage` (desktop), `MemStorage` (tests, with fault injection: fail or tear the N-th write), Kotlin SAF implementation through `ffi/`.

### 5.2 Vault API (sketch)

```rust
pub struct Vault { /* storage, MK subkeys in Secret<..>, current root, settings, lock */ }

impl Vault {
    pub fn create(storage, opts: CreateOptions) -> Result<(Vault, RecoveryPhrase)>;
    pub fn unlock(storage, secret: UnlockSecret, mode: AccessMode) -> Result<(Vault, UnlockReport)>;
    pub fn lock(self);                                   // zeroize everything

    pub fn list(&self, path: &VaultPath) -> Result<Vec<Entry>>;
    pub fn stat(&self, path: &VaultPath) -> Result<Entry>;
    pub fn read_file(&self, path: &VaultPath) -> Result<impl Read>;   // streaming, verified
    pub fn import(&mut self, src: impl Read, dest: &VaultPath, meta: FileMeta) -> Result<()>;
    pub fn mkdir(&mut self, path: &VaultPath) -> Result<()>;
    pub fn rename(&mut self, from: &VaultPath, to: &VaultPath) -> Result<()>;
    pub fn remove(&mut self, path: &VaultPath, recursive: bool) -> Result<()>;
    pub fn commit(&mut self) -> Result<()>;               // batch several changes, one root write

    pub fn change_password(&mut self, slot: SlotIndex, new: Password) -> Result<()>;
    pub fn add_keyslot(&mut self, kind: NewSlot) -> Result<SlotIndex>;
    pub fn remove_keyslot(&mut self, slot: SlotIndex) -> Result<()>; // never the last one
    pub fn rekey(&mut self, progress: impl FnMut(Progress)) -> Result<()>; // new MK, rewrite all
    pub fn verify(&self, progress: impl FnMut(Progress)) -> Result<VerifyReport>;
    pub fn gc(&mut self) -> Result<GcReport>;
    pub fn settings(&self) -> &Settings;
    pub fn set_settings(&mut self, s: Settings) -> Result<()>;
}
```

`UnlockReport` carries rollback/fork warnings and whether the backup header or older root slot was used.

### 5.3 Error classes (user-facing)

| Error | Meaning shown to the user |
|---|---|
| `WrongSecret` | No keyslot opened with what you entered |
| `Tampered` | A keyslot opened, but the header MAC, a hash or an AEAD tag failed |
| `Damaged` | Structure is unreadable (e.g. both root slots invalid) without a sign of tampering |
| `Unsupported` | Newer format version or unknown required feature — update Tijori |
| `Locked` | Another writer holds `.lock`; opened read-only |
| `RollbackWarning` / `ForkWarning` | Not errors: warnings in `UnlockReport` |
| `Io` | Underlying storage problem (drive removed, full, read-only) |

## 6. Milestones

Each milestone ends with: all tests green in CI, `cargo clippy -- -D warnings` clean, `cargo deny check` clean, and a short summary written to `docs/progress.md`.

### Milestone 0 — Repository and CI

**Tasks**
- Create the workspace and every crate/folder in §3 with placeholder `lib.rs`/`main.rs`.
- Copy Appendix A into `spec/SPEC.md` verbatim.
- Add licences per §1, `README.md` (what Tijori is, status: pre-alpha, do not trust with real data yet), `SECURITY.md` (private disclosure process), `CONTRIBUTING.md`.
- `rust-toolchain.toml` (pinned stable), `rustfmt.toml`, `deny.toml`.
- GitHub Actions: fmt, clippy, test on `ubuntu-latest` and `macos-latest`; `cargo deny`; `cargo audit`.

**Done when** CI is green on an empty-but-compiling workspace.

### Milestone 1 — Crypto, format and test vectors (no I/O)

**Tasks**
1. `spec/generator/`: Python script producing every vector file listed in Appendix A §15 using PyNaCl/libsodium. Objects and root pointers are produced once with random headers/nonces and stored; Rust tests **decrypt** them (secretstream cannot be made deterministic) and round-trip their own.
2. `core/crypto`: thin, typed wrappers over dryoc — `argon2id`, `aead_encrypt/decrypt`, `StreamPush/StreamPull`, `blake2b(key?, msg)`, `kdf(mk, id)`, `random_bytes`. All key types are newtypes with `Zeroize`.
3. `core/padding.rs`: Padmé exactly as Appendix A §7.3.
4. `core/names.rs`: NFC normalization and name validation (§11).
5. `core/format/`: parse/serialize for header, keyslot, root pointer, directory CBOR, object stream framing — pure functions over byte slices, enforcing all limits in §12 **before** any allocation or KDF.
6. `core/recovery.rs`, `core/strength.rs`.
7. Fuzz targets in `fuzz/` for: header parser, root pointer decrypt+parse, directory CBOR parser, object stream reader.

**Done when**
- Every vector file passes, including all negative cases with the exact error class.
- Property tests: encrypt→decrypt round trips for random sizes 0 B to 1 MiB across chunk boundaries (0, 1, 65535, 65536, 65537, 131072 …); Padmé never exceeds 11.7% overhead and is monotonic.
- Each fuzz target runs 10 minutes locally without a crash.

### Milestone 2 — Vault engine

**Tasks**
1. `Storage` trait, `StdFsStorage`, `MemStorage` with fault injection.
2. `Vault::create`: random MK and `vault_uuid`, Argon2 calibration (start at minimum `t` for the memory default, raise `t` until ≈1 s, cap per §12), password keyslot + recovery keyslot, empty root directory, root slot A at `rev = 1`, header + backup, `README-TIJORI.txt`.
3. `Vault::unlock` exactly per Appendix A §6, including backup-header fallback and A/B root selection.
4. Copy-on-write writes and `commit` per §9.1; write lock per §9.2; GC per §9.3 (keeps objects reachable from **both** root slots).
5. Keyslot management, password change, `rekey` (new MK; rewrite every object; old objects removed by GC only after the new root commits).
6. Rollback record per §10 in the app data dir, encrypted with a key stored via `keyring`.
7. `verify`: walk the tree, check every hash, decrypt every chunk.
8. Neutralize timestamps on every written file (best effort).

**Done when**
- Crash tests: with `MemStorage`, for each write index N in a multi-file commit, injecting a failure or torn write at N leaves a vault that unlocks to **either** the previous or the new state, never neither, and `verify` passes.
- Tamper tests: flipping any single byte of any file on disk yields `Tampered` (or `WrongSecret` for keyslot bytes before MAC check) — never wrong plaintext.
- Swap tests: swapping two object files, swapping root slots, replaying an older root slot → detected as specified.
- Lock tests: second writer is refused and opens read-only.
- A 2 GiB file imports and exports with flat memory use (streaming).

### Milestone 3 — CLI (`tijori`)

Commands (all accept `--vault <drive or TIJORI path>`; auto-detect a single mounted vault if omitted):

```
tijori init <drive> [--no-padding] [--label NAME] [--keyfile PATH]
tijori shell <drive>                      # unlock once, run several commands, lock on exit
tijori ls [PATH] [-l]
tijori put <LOCAL...> <VAULT_DIR>         # files and folders, recursive
tijori get <VAULT_PATH...> <LOCAL_DIR>
tijori mkdir | mv | rm [-r] <PATH>
tijori cat <VAULT_PATH>                   # small text files to stdout
tijori passwd [--slot N]
tijori keyslot list | add --keyfile PATH | add --recovery | remove N
tijori rekey
tijori verify
tijori gc
tijori info                               # format version, slots in use, settings, rev
tijori settings [--padding on|off] [--private-only on|off] [--label NAME]
tijori mount <drive> <MOUNTPOINT>         # Milestone 4
```

Notes:
- **No background session agent in v1.** Each command prompts for the password, unlocks, does its work and locks. `tijori shell` is the only way to keep a vault unlocked across several commands.
- `init` prints the recovery phrase once, in 6 rows of 4 numbered words, with the warning: *"If you lose both your password and this recovery phrase, your files cannot be recovered by anyone."* It asks the user to type `I UNDERSTAND`, but saving the phrase is optional.
- Password prompts reject zxcvbn score < 3 with the reason and a suggestion to use a 6-word passphrase.
- Exit codes: 0 ok, 2 wrong secret, 3 tampered, 4 damaged, 5 unsupported, 6 locked, 1 other.
- Optional `tijori format <device>`: formats a drive as exFAT (`diskutil eraseDisk ExFAT …` on macOS, `mkfs.exfat` on Linux). **Destructive**: require the user to type the device name, refuse internal/system disks, and never run without explicit confirmation.

**Done when** `insta` snapshot tests cover every command's output, and an end-to-end script (`scripts/e2e.sh`) creates a vault on a loop-mounted exFAT image (Linux) / disk image (macOS), runs every command, and verifies results.

### Milestone 4 — Mount (FUSE) with host hardening

**Tasks**
1. **Spike (time-boxed, report back):** on macOS, can `fuser` run on FUSE-T (kext-free) — directly or via its libfuse-compatible library? If not, use macFUSE and document the system-extension approval step. Write findings to `docs/macos-fuse.md` and **ask the user before continuing**.
2. `tijori-mount`: read-write FUSE filesystem over the `Vault` API. Writes buffer into a temp **in memory or on the RAM disk**, never on the host disk; commit on `flush`/`release`, coalescing frequent saves (commit at most every 2 s per file and on unmount).
3. Mount only for the current user (`default_permissions`, mode 0700, no `allow_other`).
4. Refuse to mount when the vault setting **private-only** is on.
5. Hardening on mount:
   - macOS: create `.metadata_never_index` at the mount root, run `mdutil -i off <mountpoint>`, `tmutil addexclusion <mountpoint>`; mount with `noappledouble` / `nobrowse` options where supported; on lock, clear Quick Look cache for the mount (`qlmanage -r cache`).
   - Linux: add the mountpoint to `tracker`/`baloo` exclusions when those indexers exist; mount under `$XDG_RUNTIME_DIR/tijori/<label>`.
6. Auto-unmount + lock on: drive removal, system sleep, screen lock, logout, idle timeout (default 15 min, configurable).

**Done when** Finder (macOS) and Nautilus/Dolphin (Linux) can browse, open, edit and save files; pulling the drive while mounted leaves a vault that unlocks and verifies; Spotlight finds nothing inside a mounted vault.

### Milestone 5 — Desktop app (Tauri 2, macOS + Linux)

**Backend (`desktop/src-tauri`)**
- Holds at most one unlocked `Vault` per drive in a `Mutex`; all crypto stays here.
- Commands (each returns plain data, never keys): `list_drives`, `create_vault`, `unlock`, `lock`, `list_dir`, `stat`, `import_paths`, `export_paths`, `mkdir`, `rename`, `remove`, `read_text`, `write_text`, `read_preview` (images/PDF bytes for viewers, size-capped), `open_external`, `mount`, `unmount`, `change_password`, `keyslots_*`, `rekey`, `verify`, `get_settings`, `set_settings`, `password_strength`.
- Long operations stream progress events and are cancellable.
- **Drive watcher:** macOS — watch `/Volumes`; Linux — watch `/media/$USER`, `/run/media/$USER`, `/mnt`. A drive is a Tijori drive if `TIJORI/vault.header` exists. Removal → lock + unmount immediately.
- **RAM disk for "open in other app" (Private mode):** macOS — `hdiutil attach -nomount ram://<sectors>` then `diskutil erasevolume APFS TijoriTmp <dev>` (size = 2× file, max configurable); Linux — `/dev/shm/tijori-<random>/` mode 0700. Watch the decrypted copy; re-encrypt and commit on every save; on close or lock overwrite and delete it, then detach the RAM disk.
- Password strings arrive from JS and cannot be wiped in JS memory: move them into `Secret` immediately in Rust and keep their JS lifetime as short as possible (clear the input field and state right after submit).
- Tauri 2 security: strict CSP (`default-src 'self'`), no remote URLs, capability files granting only the commands above, `dialog` plugin for file pickers, **no `fs` plugin exposed to the frontend**, devtools disabled in release builds.

**Frontend (`desktop/src`)**
- Screens: Drive list → Create vault wizard (password + strength meter, optional keyfile, recovery phrase screen with warning, padding toggle defaulting **on**) → Unlock → Vault browser.
- Vault browser: breadcrumb, list/grid, drag-and-drop import, export, new folder, rename, delete (with confirmation), search by name (in memory only).
- Mode switch: **Mount in Finder / Files** (default) or **Private mode**. Show a small badge of the active mode.
- Built-in viewers: images, PDF (PDF.js bundled locally), plain-text editor (max 10 MiB). Other files: "Open with default app" via the RAM disk.
- Settings: auto-lock timeout, padding, private-only, keyslots (add keyfile / recovery, change password, remove), re-key, verify.
- Accessible: keyboard navigation, focus states, light and dark themes.

**Packaging:** Tauri bundler → macOS `.dmg` (universal: arm64 + x86_64), Linux AppImage + `.deb` (+ `.rpm` if easy). Document macOS code signing and notarization (needs an Apple Developer account — **ask the user** before setting it up). The CLI ships separately via `cargo install` and release archives.

**Done when** a non-technical user can create, unlock, use and lock a vault on both macOS and Linux without the terminal; removal of the drive always locks; manual test checklist in `docs/desktop-qa.md` passes.

### Milestone 6 — Android (Kotlin)

**Tasks**
1. `ffi/`: UniFFI interface exposing the Vault API (blocking functions, called from Kotlin coroutines on `Dispatchers.IO`) and a **callback interface `KotlinStorage`** implementing the `Storage` trait.
2. Build: `cargo-ndk` for arm64-v8a, armeabi-v7a, x86_64; Gradle task that runs it and generates Kotlin bindings; bindings in module `tijori-core-bindings`.
3. Storage on Android: user picks the USB drive root once with `ACTION_OPEN_DOCUMENT_TREE`; persist the URI permission; implement `KotlinStorage` with `DocumentsContract`/`ContentResolver` (not `DocumentFile`, which is slow). `renameDocument` cannot overwrite, so `write_atomic` deletes then renames — safe because of the A/B root scheme. Detect when the drive is unplugged and lock.
4. Compose UI mirroring the desktop flow: drive picker, create vault, unlock, browser, import (system picker), export/share (decrypt to app-private cache, share via `FileProvider`, wipe after), image/PDF viewer, text editor, settings.
5. Argon2 default on Android: 128 MiB, `t` tuned to about 1 s; must also open desktop-created vaults (256 MiB) — test on a 3 GB RAM device/emulator.
6. Security: `FLAG_SECURE` on vault screens (no screenshots/recents thumbnails), lock on background after a short grace period (default 30 s), lock on USB detach, wipe caches on lock.
7. **Stretch (6b):** `DocumentsProvider` exposing the unlocked vault to other apps (read via `ParcelFileDescriptor` pipes; writes buffered in app-private memory/cache and re-encrypted on close). **Stretch (6c):** optional biometric quick-unlock for the current session only, off by default.

**Done when** a vault created on macOS opens, edits and saves on Android and back again, with the shared vectors passing in an Android instrumentation test; the app never writes plaintext outside its private cache, and that cache is empty after lock.

### Milestone 7 — Hardening and release prep

# Appendix A — Tijori Vault Format Specification v1.0 (draft)

## 1. Conventions

- **MUST / MUST NOT / SHOULD / MAY** as in RFC 2119.
- All integers are **little-endian**, unsigned unless stated. `a || b` is byte concatenation.
- `"TJRI ..."` strings are ASCII with no terminator.
- KiB = 1024 bytes; MiB = 1024 KiB.
- Text is UTF-8. Passwords and names are normalized to **Unicode NFC** before use.
- Structured data is **deterministic CBOR** (RFC 8949 §4.2.1): definite lengths, shortest integer forms, map keys sorted.
- Out of scope for v1: hidden volumes, compression, deduplication, symlinks, extended attributes, hardware keys.

## 2. Drive layout

The vault is the folder `TIJORI` at the root of an **exFAT** volume.

```
/ (exFAT root)
├── README-TIJORI.txt        optional, plain text
└── TIJORI/
    ├── vault.header         1120 bytes (§5)
    ├── vault.header.bak     byte-identical backup
    ├── vault.root.a         root pointer slot A (§8)
    ├── vault.root.b         root pointer slot B
    ├── .lock                only while a writer is active
    └── objects/
        └── 3f/
            └── 3f9a…e1.tjo  64 lowercase hex chars + .tjo
```

- Object path: `objects/<first 2 hex chars>/<64 hex chars>.tjo`.
- Files and directories are both objects and look identical on disk.
- `*.tmp` files are incomplete writes; readers MUST ignore them.

## 3. Primitives

| Name | Algorithm | libsodium equivalent | Sizes |
|---|---|---|---|
| `ARGON2ID` | Argon2id v1.3, **lanes = 1** | `crypto_pwhash` (`ALG_ARGON2ID13`), memlimit = `mem_kib × 1024`, opslimit = `t` | salt 16, out 32 |
| `AEAD` | XChaCha20-Poly1305 (IETF) | `crypto_aead_xchacha20poly1305_ietf_*` | key 32, nonce 24, tag 16 |
| `STREAM` | secretstream XChaCha20-Poly1305 | `crypto_secretstream_xchacha20poly1305_*` | key 32, header 24, +17 bytes per chunk |
| `H(key, msg)` | BLAKE2b, 32-byte output, key optional | `crypto_generichash` | key none or 32 |
| `KDF(key, id)` | BLAKE2b subkey derivation, context `"TJRIv1__"` | `crypto_kdf_derive_from_key` | key 32, id u64, out 32 |

- `KDF(key, id)` equals BLAKE2b(key = key, message = empty, out = 32, salt = `LE64(id) || 0x00×8`, personal = `"TJRIv1__" || 0x00×8`).
- Lanes are fixed at 1 (libsodium supports only 1). Readers MUST reject other values.
- Randomness from the OS CSPRNG only. All tag/MAC/hash comparisons constant-time.
- Every hashed message begins with a distinct ASCII label, giving domain separation.

## 4. Key hierarchy

The Master Key **MK** is 32 random bytes, generated at creation, never stored unwrapped.

Key-encryption keys:

```
Type 1  password:            KEK = ARGON2ID(NFC(password), salt, m, t)
Type 2  password + keyfile:  A   = ARGON2ID(NFC(password), salt, m, t)
                             KF  = H(none, "TJRI keyfile v1" || keyfile_bytes)
                             KEK = H(KF, "TJRI kek v1" || A)
Type 3  recovery phrase:     E   = 32-byte entropy decoded from 24 English BIP-39 words
                             KEK = H(E, "TJRI recovery v1" || salt)
```

Subkeys: `K_hmac = KDF(MK, 1)` (header MAC), `K_root = KDF(MK, 2)` (root pointers), `K_obj = KDF(MK, 3)` (object keys). Ids ≥ 4 reserved.

Object keys:

```
object_key = H(K_obj, "TJRI obj v1" || kind || object_id)
kind = 0x01 file, 0x02 directory; object_id = 32 random bytes
```

Changing a password rewraps MK only. Re-keying (new MK, every object rewritten) is a separate operation.

## 5. Vault header

`vault.header` is exactly **1120 bytes**.

### 5.1 Header layout

| Offset | Size | Field | Rule |
|---|---|---|---|
| 0 | 4 | `magic` | ASCII `TJRI` |
| 4 | 2 | `format_major` | `1` |
| 6 | 2 | `format_minor` | `0` |
| 8 | 4 | `required_features` | Readers MUST refuse unknown bits. v1: `0` |
| 12 | 4 | `optional_features` | Unknown bits MAY be ignored. v1: `0` |
| 16 | 16 | `vault_uuid` | Random, fixed for the vault's life |
| 32 | 1024 | `keyslots[8]` | 8 × 128 bytes (§5.2) |
| 1056 | 32 | `reserved` | Zero |
| 1088 | 32 | `header_mac` | `H(K_hmac, header bytes 0..1088)` |

### 5.2 Keyslot (128 bytes)

| Offset | Size | Field | Rule |
|---|---|---|---|
| 0 | 1 | `slot_type` | 0 empty, 1 password, 2 password + keyfile, 3 recovery; 4 reserved (FIDO2) |
| 1 | 1 | `kdf_id` | 1 Argon2id (types 1, 2); 2 BLAKE2b (type 3) |
| 2 | 2 | `reserved` | Zero |
| 4 | 4 | `argon_mem_kib` | Zero for type 3 |
| 8 | 4 | `argon_ops` | Zero for type 3 |
| 12 | 4 | `argon_lanes` | `1`; zero for type 3 |
| 16 | 16 | `salt` | Random; new on every rewrap |
| 32 | 24 | `nonce` | Random per wrap |
| 56 | 48 | `wrapped_mk` | `AEAD(KEK, nonce, MK, ad)` = 32 + 16 tag |
| 104 | 24 | `reserved` | Zero |

Empty slot = 128 zero bytes.

```
ad = "TJRI ks v1" || vault_uuid || slot_index (1 byte, 0–7) || keyslot bytes 0..32
```

### 5.3 MAC and backup

- MAC is checked after MK is unwrapped (constant time).
- `vault.header.bak` MUST equal `vault.header`. Update order: backup first, then primary, each tmp → fsync → rename.
- If the primary fails to parse, unwrap or verify, try the backup. If a keyslot opens but both fail the MAC, report **Tampered**.

### 5.4 Default Argon2id parameters

| Created on | Memory | t | Target |
|---|---|---|---|
| Desktop | 262,144 KiB (256 MiB) | tuned, ≥ 3 | ≈ 1 s on the creating machine |
| Android | 131,072 KiB (128 MiB) | tuned, ≥ 4 | ≈ 1 s on the creating phone |

## 6. Unlock procedure

1. Read `vault.header`: exactly 1120 bytes, magic `TJRI`, `format_major = 1`, no unknown required bits.
2. Check every non-empty slot against §12 limits; any violation → reject this header (then try backup).
3. Choose candidate slots: password → types 1, and 2 if a keyfile was given; recovery phrase → type 3.
4. For each candidate derive the KEK and open `wrapped_mk`. First success wins. None → **WrongSecret**.
5. Derive `K_hmac`, `K_root`, `K_obj`; verify `header_mac`. Failure → repeat with `vault.header.bak`; both fail → **Tampered**.
6. Open root slots A and B (§8.1); use the valid one with higher `rev`. Neither → **Damaged**.
7. Compare with the device rollback record (§10); add warnings to the report.
8. Load the root directory object, verify its hash against the root pointer, show the tree.
9. Wipe password, KEK and keyfile bytes. Keep MK-derived keys in locked memory until lock.

## 7. Objects

### 7.1 Layout

| Offset | Size | Field |
|---|---|---|
| 0 | 1 | `object_version` = 1 |
| 1 | 24 | `stream_header` |
| 25 | varies | chunks: `STREAM` ciphertext of ≤ 65,536 plaintext bytes + 17 |

- All chunks but the last carry exactly 65,536 plaintext bytes, tag `MESSAGE`. The last carries 0–65,536 bytes, tag `FINAL`. Data after `FINAL` or a missing `FINAL` → reject.
- Every chunk's associated data = `kind || object_id` (33 bytes).
- Objects are immutable; a change gets a new random `object_id`.

### 7.2 Plaintext stream

```
plaintext = content_length (u64) || content || zero padding
total     = padme(8 + content_length)   if padding is on
          = 8 + content_length          if padding is off
```

Readers MUST check `content_length ≤ total − 8` and that all padding bytes are zero.

### 7.3 Padmé

```
E = floor(log2(L));  S = floor(log2(E)) + 1
mask = 2^(E − S) − 1
padme(L) = (L + mask) & ~mask          (L ≥ 8 here)
```

Examples (content → stored plaintext): 0 → 8; 92 → 104; 992 → 1,024; 65,536 → 67,584; 1,000,000 → 1,015,808; 10^9 → 1,006,632,960. Worst-case overhead ≈ 11.6%.

### 7.4 Observable size

On-disk size = `25 + total + 17 × ceil(total / 65536)`.

## 8. Directory tree and root pointers

### 8.1 Root pointer files (`vault.root.a`, `vault.root.b`)

| Offset | Size | Field |
|---|---|---|
| 0 | 1 | `root_version` = 1 |
| 1 | 24 | `nonce` |
| 25 | varies | `AEAD(K_root, nonce, cbor, ad)` |

`ad = "TJRI root v1" || vault_uuid || slot_letter` (ASCII `a` or `b`).

CBOR map:

| Key | Field | Type |
|---|---|---|
| 1 | `rev` | uint, +1 per commit |
| 2 | `root_id` | bytes(32) |
| 3 | `root_hash` | bytes(32) = `H(none, root object file bytes)` |
| 4 | `settings` | map: `1` padding (bool), `2` private_only (bool), `3` label (text ≤ 64 bytes) |
| 5 | `written_at` | uint, Unix seconds |
| 6 | `writer_id` | bytes(16) |

### 8.2 Directory objects (kind 0x02)

Content CBOR: `{1: dir_version = 1, 2: [entries…]}`, entries sorted by name bytes.

| Key | Field | Type | Rule |
|---|---|---|---|
| 1 | `name` | text | NFC, §11 |
| 2 | `kind` | uint | 1 file, 2 directory |
| 3 | `id` | bytes(32) | child object ID |
| 4 | `hash` | bytes(32) | `H(none, child object file bytes)` |
| 5 | `size` | uint | content bytes (files only) |
| 6 | `mtime` | int | Unix milliseconds |
| 7 | `mode` | uint | optional; bit 0 = executable |

Readers MUST verify `hash` before decrypting a child. Unknown keys: readers ignore; writers keep them on unchanged entries.

## 9. Writing

### 9.1 Commit

1. Take the write lock.
2. Write new file objects: `<id>.tjo.tmp` → fsync → rename → fsync folder.
3. Write new directory objects for every folder from the change up to the root.
4. Write the new root pointer (`rev + 1`) into the slot holding the **lower** (or invalid) `rev`, via tmp → fsync → rename. **Commit point.**
5. Update the device rollback record.
6. Release the lock. Old objects are left for GC.

### 9.2 Lock

`TIJORI/.lock` created with exclusive-create, containing a random lock ID, writer ID and timestamp. If present, open read-only and say who holds it. A lock older than 10 minutes with no live process MAY be broken after user confirmation. One writer at a time.

### 9.3 Garbage collection

Walk trees reachable from **both** root slots; delete `.tjo` files not reached and any `.tmp` files.

## 10. Rollback detection

Per device, outside the drive: `vault_uuid → { max_rev, root_hash, last_seen }`, encrypted with a key in the OS keychain.

| Drive vs record | Result |
|---|---|
| No record | First use; create record |
| `rev` > `max_rev` | Normal; update |
| `rev` = `max_rev`, same hash | Normal |
| `rev` = `max_rev`, different hash | **Fork warning** |
| `rev` < `max_rev` | **Rollback warning** |

Warnings offer: continue read-only, accept the older state, or cancel.

## 11. Names and metadata

- 1–255 bytes UTF-8 after NFC. No `/`, no NUL, not `.` or `..`.
- Unique within a directory (NFC bytes). Case-sensitive.
- Export/mount to case-insensitive hosts shows clashing or reserved names with a visible suffix; never silently overwrites.
- Stored: `mtime`, optional executable bit. Not stored: creation time, owner, ACLs, xattrs. Symlinks and special files are skipped on import with a warning.
- Writers SHOULD set modified/accessed time of every vault file to 2000-01-01T00:00:00Z.

## 12. Parser limits

| Item | Min | Max |
|---|---|---|
| `vault.header` size | 1120 | 1120 |
| `argon_mem_kib` | 65,536 | 1,048,576 |
| `argon_ops` | 2 | 64 |
| `argon_lanes` | 1 | 1 |
| Non-empty keyslots | 1 | 8 |
| Root pointer file | 41 bytes | 4 KiB |
| Directory plaintext | 8 bytes | 64 MiB |
| Entries per directory | 0 | 200,000 |
| Tree depth | 1 | 256 |
| Name length | 1 byte | 255 bytes |
| Object plaintext | 8 bytes | 2^62 bytes |

Writers SHOULD NOT create slots above 256 MiB. CBOR readers: definite lengths only; no tags, floats or undefined; reject duplicate keys, non-shortest integers and type mismatches.

## 13. Versioning

| Change | Mechanism | Old reader |
|---|---|---|
| Optional new field | New CBOR key | Ignores, preserves |
| Optional feature | `optional_features` bit | Ignores |
| Feature changing how data is read | `required_features` bit | Refuses, names required version |
| New keyslot / KDF | New `slot_type` / `kdf_id` | Skips slot |
| Incompatible redesign | `format_major` = 2 | Refuses |

Upgrading a vault to a newer format MUST ask the user first.

## 14. Security considerations

Visible to anyone holding the drive: that it is a Tijori vault; the number of objects; Padmé-rounded sizes; which keyslot types are used; Argon2 parameters; some exFAT creation times.

Known limits: old headers can survive on flash after a password change (only re-keying revokes an old password); deleted ciphertext can survive on flash; rollback is detected only on devices that saw the newer state; a compromised host sees everything while unlocked; weak passwords are the biggest risk (writers MUST require zxcvbn score ≥ 3).

Deliberate choices: no compression, no deduplication, random 192-bit nonces, immutable objects, keys zeroized and wiped on lock, sleep, drive removal and idle.
